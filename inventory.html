Not-On-Truck Adjustments

When a customer is credited because an item didn't make it onto the truck, that product is still in the warehouse and has to go back into inventory. This workflow turns the scanned credit register into a checked spreadsheet, then keys every line back into the right slot.

How it runs

  1. The Email Watcher spots the credit register email and queues the "Not On Truck" scan.
  2. It reads the scan and builds a spreadsheet. Each item number is read twice and cross-checked.
  3. Validation gate: every return-code subtotal and the report total must match the register's printed totals to the penny before anything is keyed.
  4. For each item, it checks the item history. If someone already fixed it after the last sale, it's skipped.
  5. It opens the item's slots in the green screen and posts the quantity back with reason code NT.
  6. It writes a results file in which posted plus held lines must equal the register's total.
Starts when
The daily credit register arrives by email. If it hasn't arrived by 1 PM, Doug gets a notification.
Produces
Not On Truck Adjustments.xlsx (two tabs) and a results text file listing every posting.
Built-in safety
Duplicate lines are combined, negative slots are fixed in the right order, and certain items are never adjusted automatically.
Doug's part
Answers questions on held items, such as whole-muscle meat or items that need expiration dates, all at the end of the run.

Handwritten Transfer Sheets

The meat room records its transfers by hand on a printed form, which is then scanned. This workflow reads the handwriting, including strike-throughs, arrows and margin notes, and builds the adjustment workbook.

How it runs

  1. It rotates and zooms the scanned pages: four grid pages, a chicken and piece-code page, and an optional freezer page.
  2. It reads each row and compares doubtful digits against the same writer's other digits, such as an open-top 4 vs. a closed-loop 9.
  3. When a weight looks off, it checks the item's normal minimum, maximum and average weight in the ERP.
  4. It follows the sheet's own marks: strike-throughs, arrows, brackets and rows that spill over.
  5. It writes every handwritten value in bold blue, so it's obvious what came from the sheet.
  6. It reports a "Please check" list of every doubtful digit and its alternative reading.
Starts when
The meat room's transfer scan arrives by email (an MR job).
Produces
MR Adjustment Sheet.xlsx with Chicken & Piece Codes, Meat Room and Freezer tabs.
Gets smarter
Doug highlights any misread in yellow, and the lesson is added to the skill.

Meat Room Adjustments

Once the transfer sheet is transcribed, every line has to be posted to the warehouse system and imported into the ERP. This workflow does it in fast, scripted batches, then emails the meat team a clean summary.

How it runs

  1. It sets up the screen: unneeded windows are minimised (never closed), and the item screen goes beside the green screen.
  2. It looks up every item's slots and its ERP numbers in one pass, and writes the math for each line.
  3. It posts in batches of six. The posting rule depends on the section: chicken, piece codes, the grid or the freezer.
  4. It imports the batch into the ERP and confirms the "N item adjustments imported" message.
  5. It re-checks the ERP, writes the results file and sends one results email once every question is settled.
Starts when
Right after the handwritten sheet is transcribed. There's no waiting for a review.
Rules it follows
Quantity and pounds must have the same sign. A negative meat weight is reset to quantity × average weight.
Produces
A results file showing each slot's old → new value, plus one summary email with the workbook attached.
Doug's part
Answers batched item questions. The email waits until he has.

Weekly Final-Count Adjustments

Once a week the meat room does a physical count. This workflow makes the system match it, keeping the warehouse terminal and the ERP in agreement along the way.

How it runs

  1. It picks up the weekly count spreadsheet from email. Only rows with a count are used.
  2. It looks up each item's true quantity and average weight in the ERP.
  3. It adds up all of the item's slots in the warehouse terminal.
  4. If the terminal and the ERP disagree, it first posts a sync adjustment (DK) so they match.
  5. It then posts MF = count − ERP quantity on the pick slot, with weight = quantity × average weight.
  6. It imports into the ERP, verifies the result and sends the summary email.
Starts when
The weekly count spreadsheet arrives by email.
Safety
A sheet is never keyed twice. An average weight of 0.00 means "hold and ask", never a guess.
Produces
A results file and one summary email in the same format as Meat Room Adjustments.
