PO Discrepancy Check

Vendors send order confirmations that don't always match what we ordered: a price creeps up, a quantity gets cut, or an item disappears. This workflow checks every line and marks up the PO the way a buyer would with a red pen.

How it runs

  1. A copier scan arrives by email holding one or more POs and their vendor confirmations, with pages in any order.
  2. A script sorts the pages and pairs each PO with its confirmation. A quick contact sheet double-checks the pairing.
  3. One helper agent per PO checks the pairs in parallel, so a ten-PO scan takes about as long as a single PO.
  4. The math is checked on both documents: quantity × unit cost = extended, the lines add up to the printed total, and catch weight matches the pack size.
  5. Every difference is marked on the PO pages, and a summary page explaining the dollar difference is added.
  6. The vendor-confirmed prices and quantities are then keyed into the ERP's Change Purchase Order screen, so the PO is correct before the truck arrives.
Starts when
A scan with a vendor confirmation lands in the inbox. The Email Watcher queues it automatically.
Produces
One PDF per PO, in this order: annotated PO pages → vendor confirmation pages → summary page. Filed by vendor and date.
Counts as a discrepancy
Any price or quantity difference, a line on only one document, a different pack size, or a price confirmed at $0.00.
Doesn't count
Catch-weight overage, per-lb vs. per-case pricing that ties to the cent, and rounding in the last printed digit.
Doug's part
Reviews the finished files. When it isn't sure which number is the price, it asks him instead of guessing, then remembers his answer for that vendor.

Today's Receiving POs

Every morning the receivers need a printed list of every PO due in today. This workflow runs the report, cleans it up and prints it before anyone asks.

How it runs

  1. At 7:35 AM it checks the print log. If today's list already printed, it stops.
  2. It confirms the network drive is connected and the default printer is the office printer.
  3. It runs the ERP's PO Status report (Summary style, today's required date) and saves it as a PDF.
  4. It reads the PDF and checks that every vendor subtotal and the report total add up.
  5. It builds a clean Excel sheet and prints it in the background, without using the screen.
Starts when
Automatically, every weekday at 7:35 AM.
Produces
A one-page-wide printed list, plus Today's Receiving PO's.xlsx.
Checks
Subtotals and the grand total must reconcile. Odd lines, such as a test vendor, are flagged.
Doug's part
None. He gets a one-line notification when it's printed.

Order Acknowledgment Reformatter

Some vendors export order acknowledgments as long text files that repeat the same header on every page. This workflow strips the repetition, so the whole order fits on one readable page that's named by its PO number.

How it runs

  1. Drop in the vendor's raw acknowledgment text export.
  2. It finds the customer PO number and keeps the order header once.
  3. It removes the repeated page headers, footers and page breaks.
  4. It lines the item rows up into a compact single-page layout.
  5. It saves the result as {PO number}.TXT, ready to compare against the PO.
Starts when
A vendor acknowledgment export needs to be reviewed.
Produces
One compact text file named by PO number.
Why it matters
A three-page printout becomes one page, and the file name says exactly which PO it belongs to.

Discount Deviation Matching

Vendors offer "deviation" pricing: discounts on specific items for specific periods. This workflow matches what we carry against the vendor's deviation list, so no eligible discount gets missed.

How it runs

  1. Takes the vendor inventory report and the vendor's deviation (discount) price list.
  2. Matches items between the two, even where codes or descriptions are formatted differently.
  3. Checks each match for eligibility, such as the date range and pack size.
  4. Builds a Deviation Matches workbook listing every eligible item and its discount.
  5. Files the original reports away so the folder stays clean.
Starts when
A vendor sends an updated inventory report or deviation list.
Produces
A workbook of eligible items with deviation prices and the savings per case.
Why it matters
Discounts we qualify for get claimed instead of slipping by.
