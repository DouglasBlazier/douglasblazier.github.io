A normal weekday

  1. 7:30 AMThe remote desktop opens and login macros sign in to the ERP and terminal. No password is ever typed by Claude.
  2. 7:31 AMThe Worker Desk and PO Desk start themselves. I approve screen access once, and that covers the whole day.
  3. 7:35 AMToday's Receiving POs runs and prints.
  4. 8 AM–5 PMThe Email Watcher checks the inbox every minute and turns paperwork into jobs.
  5. 9:00 AMThe tonnage report runs.
  6. All dayJobs run in priority order. Questions are saved for the end of each run, never mid-run.
  7. 5:00 PMThe watcher posts an end-of-day summary and writes "lessons learned" notes for tomorrow.
How jobs are handed off
Plain text job files in a shared queue folder. A desk claims a job by moving it to "Working", so two desks can never take the same job.
Other job types
Out of ERP / Back In: when accounting needs everyone out, every keying job pauses cleanly and resumes later. Vacation calendar: printed monthly with no screen needed.
House rules
Never delete anything; files are moved instead. Every run is timed. Every job writes a report.
Doug's part
One approval in the morning, and answers to batched questions.

Morning Brief

A single styled page that's ready when I sit down, showing what's on the calendar, what's waiting in the inbox and what the automations already finished.

How it runs

  1. It runs on weekday mornings, or whenever I type /morning.
  2. It pulls today's meetings and the emails that need a reply.
  3. It adds the overnight status of the queue and the desks.
  4. It builds a clean page I can read in a minute.
Produces
A styled one-page brief.
Why it matters
I start the day knowing what's waiting, instead of digging for it.

Self-Healing Sign-Ins

Automation is only useful if it keeps running when something goes wrong. These safeguards handle the everyday problems: an app crashes, a session times out, a network drive drops or two jobs need the screen at once.

What it handles

  1. ERP crash: reopens it, lets the login macro sign in, then re-checks the item it was working on before continuing.
  2. Login screen: hands off to a sign-in skill that uses saved login macros. Claude never types a password.
  3. Network drive dropped: a reconnect skill restores it, then restarts the job that failed.
  4. Email or browser down: sends one notification, retries every minute, then runs a catch-up check when it's back.
  5. Two jobs want the screen: a shared "computer lock" file lets only one job drive the screen at a time. Others wait and retry.
  6. Job stuck: if a job waits in the queue more than 10 minutes, I'm notified that a desk isn't running.
Safe to re-run
Every job first checks whether its work is already done, using results files, the print log or a file fingerprint. Nothing posts twice.
Morning recovery
Jobs left in "Working" from yesterday go back into the queue automatically.
Doug's part
Usually nothing. If it can't fix something, it tells me exactly what's wrong.
